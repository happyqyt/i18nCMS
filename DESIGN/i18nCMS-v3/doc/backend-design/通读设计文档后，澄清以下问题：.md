通读设计文档后，澄清以下问题：

1. 新建系统时在指定仓库创建子目录，并将目录链接绑定到系统信息，由浏览器 isomorphic-git 在 master 分支进行操作（新建文件夹+空 locale 种子文件+VERSION.txt）
2. 系统就绪后第 2 步是 新建开发项目：从 master 拉 dev-{项目key} 分支（key由用户填写，有字母、下划线、中横线组成）。支持多个开发项目并行。
3. 发布弹窗必填发布描述，然后修改VERSION.txt，内容如下：

```
VERSION
SERVICE.NAME={项目key}

SERVICE.VERSION=V1.0.0.0
CHANGELOG
{发布描述}
```

1. 前端将开发分支合入 master，基于 master 打 tag i18n/v{x.x.x.x}（取自VERSION.txt中的版本号）。该项目状态变为「已发布」，远端开发分支本期一律保留。同一项目可继续在该分支修改并再次发布，每次重新版本号递增打新 tag。
2. 所有系统放在同一git仓库下，一个系统一个目录
3. Git 后端接口保留，字段稍后确认。
4. 硬删除系统：系统删除后，删除远端仓库。
5. 删除系统语种: 删除系统语种后，删除远端仓库中的语种文件。
6. 删除开发项目: 删除开发项目后，删除远端开发分支。
7. i18n_app_git 是否可以合并入 i18n_app_system？毕竟应用系统和仓库是一一对应的。同理，i18n_app_tag也可以并入i18n_dev_project，只需记录最新tag即可。
8. saveAppGit需要保留，后端新建系统后调用保存和git仓库的绑定信息。
9. 业务流程图调整：
  1. BEnd登录 -> getAppList(携带登录账号信息）（云端根据账号信息自去判断超管信息，然后返回可见APP数据）-> ......
  2. 回滚master分支提到和“addProject”并行
  3. 前端在开发分支改 locale JSON -> commit + push -> 发布？->...
10. **Git 文件**：`{app_key}/{langCode}.json` ，app_key为应用系统目录，分组 Key 作为json文件里的 嵌套 key；同目录 `.i18n-cms.json` 含 `groupList`（groupKeyPath/groupName/screenshotUrl）与 `textList`（groupKeyPath/textKey）。json文件里的顺序就是显示顺序。业务应用只消费 `{langCode}.json`。
11. **种子文件**：master 初始化时每个启用语种一个 `{}`，以及空的 `.i18n-cms.json`，以及VERSION.txt。
12. Git 后端接口（saveAppGit / confirmMasterInit / confirmProjectBranch）都保留，因为都是创建系统后的关联操作。
